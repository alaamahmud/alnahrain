# خطة تجربة FIB بالبيئة التجريبية — «رابط دفع لفاتورة»
**كتبها:** يوسف (مهندس الحلول الذكية) · **التاريخ:** 2026-11-02
**الموافقة:** المالك وافق من اللوحة على «حساب تجريبي ببيئة FIB، بدون أموال حقيقية» (n-fib-sandbox).
**تنبيه:** إحنا ما سجلنا أي حساب وما دخلنا أي بيانات. التسجيل يسويه المالك بنفسه، والمفاتيح تنحط بإعدادات البيئة فقط، مو بالريبو.

## 1) خطوات التسجيل للمالك (خطوة بخطوة)
1. **افتح نموذج طلب الربط:** https://fibtask.atlassian.net/jira/software/c/form/366f78be-e7df-4e5c-acf9-56b94b5d7971?from=directory
   - موقع FIB يكول «سجّل بالبيئة التجريبية أولاً» بس ما يعطي صفحة تسجيل منفصلة. صفحة SSO تكول للتفاصيل «عبّي نموذج FIB Integration Request واكتب سؤالك بخانة Details». يعني النموذج هو الطريق المتاح.
   - بخانة Details اكتب بوضوح: «نطلب مفاتيح البيئة التجريبية (sandbox/stage) لـ Web Payments فقط، للتجربة بدون أموال حقيقية».
2. **المعلومات اللي يطلبها النموذج:** غير متوفر. النموذج ما ينفتح بدون دخول لحساب Atlassian، فما كدرنا نشوف حقوله (وما حاولنا ندخل). المتوقع إن المالك يحتاج حساب Atlassian أو إيميل حتى يفتحه، وهذا يسويه هو بنفسه.
3. **بديل التواصل:** دليل الـ SDK الرسمي يذكر الإيميل integration@fib.iq (مذكور هناك لمفاتيح الإنتاج). والهاتف بموقع FIB: 6977 أو 0662206977. أي رسالة لـ FIB يكتبها ويرسلها المالك بنفسه.
4. **شنو يرجع من FIB:** `client_id` و`client_secret` للبيئة التجريبية (حسب دليل الـ SDK). صفحة SSO تذكر كذلك «SSL Certificate»، بس هذا لميزة تسجيل الدخول مو للدفع، وإحنا ما نحتاجه هسه.
5. **مدة الرد من FIB:** غير متوفر.
6. **رسوم البيئة التجريبية أو شروطها:** غير متوفر (الموقع يكول فقط إنها «ما تأثر على البيانات الحقيقية وما تتعامل وية الشبكات المصرفية»).
7. **بعد ما توصل المفاتيح:** المالك يحطها بنفسه كـ secrets بإعدادات البيئة (القسم 3)، ويبلّغ زيد إنها انحطت، بدون ما يكتب قيمها بأي مكان.

**للإنتاج لاحقاً (مو ضمن هذي التجربة):** نفس النموذج، وFIB تعطي مفاتيح إنتاج بعد الموافقة. هذا يحتاج موافقة جديدة من المالك.

## 2) شنو نبني بالتجربة
### النموذج: «فاتورة ← رابط دفع ← تحديث الحالة»
خدمة صغيرة مستقلة (لأن كود فاي مو موجود بالريبو). نحاكي فيها فاتورة بأرقام وهمية، وما نستعمل أي بيانات زبائن.

| الخطوة | شنو يصير | الاستدعاء (من التوثيق) |
|---|---|---|
| الدخول | الخدمة تاخذ توكن قصير العمر وتجدده قبل ما يخلص | `POST /auth/realms/fib-online-shop/protocol/openid-connect/token` بـ `grant_type=client_credentials`، أو `FIB.authenticate()` بالـ SDK |
| إنشاء دفعة | من فاتورة تجريبية: المبلغ بالدينار (أكثر من 250)، وصف قصير (رقم الفاتورة)، مدة صلاحية، ورابط الـ callback | `POST /protected/v1/payments` أو `createPayment` |
| صفحة الدفع | صفحة عربية RTL تشتغل على الموبايل، تعرض: QR، الرمز المقروء (12 حرف)، وأزرار فتح تطبيق FIB (شخصي/أعمال/شركات)، ومتى تنتهي | من الرد: `qrCode`، `readableCode`، `personalAppLink`، `businessAppLink`، `corporateAppLink`، `validUntil` |
| الاستلام عبر callback | FIB ترسل `POST` لرابطنا بيه `id` و`status`. إحنا **ما نصدّقه مباشرة**: نرجع نسأل عن الحالة من FIB ونحدّث الفاتورة | `GET /protected/v1/payments/{paymentId}/status` أو `getPaymentStatus` |
| حالة الدفع | الحالات: `UNPAID`، `PAID`، `DECLINED` (أسبابها `PAYMENT_EXPIRATION`، `PAYMENT_CANCELLATION`، `SERVER_FAILURE`)، و`REFUND_REQUESTED`، `REFUNDED` حسب دليل الـ SDK | — |
| إلغاء | إذا انلغت الفاتورة قبل الدفع | `POST /protected/v1/payments/{paymentId}/cancel` (يرجع 204) |
| استرجاع (اختياري) | نجربه إذا البيئة التجريبية تسمح | `refundPayment` (ضمن مدة `refundableFor` من 12 ساعة إلى 7 أيام) |
| احتياط | إذا ما وصل callback، فحص دوري للحالة لحد ما تنتهي `validUntil` | `getPaymentStatus` |

### المعمارية المقترحة
```
[فاتورة تجريبية]──▶ [خدمة الدفع: Node.js 20 + @first-iraqi-bank/sdk]
                         │  ├─ مخزن توكن بالذاكرة (يتجدد قبل الانتهاء)
                         │  ├─ قاعدة SQLite: invoice_id ↔ paymentId، الحالة، الأوقات
                         │  ├─ GET  /pay/:invoiceId     صفحة الدفع (QR + رمز + روابط)
                         │  ├─ POST /fib/callback       يستلم {id,status} ثم يتحقق من FIB
                         │  └─ مهمة فحص دوري كاحتياط
                         ▼
                 [FIB stage: fib.stage.fib.iq]
```
- **ليش خدمة منفصلة:** تنربط بعدين بفاي عن طريق API صغير (إنشاء رابط لفاتورة / استلام حدث «انفتحت الفاتورة»)، فما نلمس كود فاي بالتجربة.
- **الحماية:** الـ callback ما بيه توقيع موثق، فالتحقق يكون دائماً بسؤال FIB عن الحالة. معالجة مكررة آمنة (نفس الحدث مرتين ما يسجل دفعتين). نحفظ رقم الفاتورة بـ `extraData` حتى نطابق.
- **الأسرار:** من متغيرات البيئة فقط، و`.env` موجود أصلاً بـ `.gitignore`.
- **السجلات:** رد الحالة بيه `paidBy` (اسم الدافع ورقم IBAN). ما نطبعه بالسجلات ولا نحطه على اللوحة.

### كم يوم تقريباً
| الشغل | أيام عمل (تقدير) |
|---|---|
| تهيئة المشروع، الدخول وتجديد التوكن | 1 |
| إنشاء دفعة + صفحة الدفع العربية | 1.5 |
| الـ callback + التحقق + الفحص الاحتياطي | 1.5 |
| الإلغاء، الانتهاء، والاسترجاع | 1 |
| اختبار مريم (حالات: دفع، انتهاء، إلغاء، callback مكرر أو ما وصل) | 1 |
| **المجموع** | **حوالي 5 إلى 6 أيام عمل** بعد وصول المفاتيح ورابط الـ callback |

التقدير مالتي، ولازم حيدر يراجعه. ما يشمل وقت انتظار رد FIB.

## 3) شنو نحتاج من المالك بالضبط
1. **التسجيل:** يعبّي نموذج طلب الربط بنفسه (أو يراسل FIB بنفسه) ويطلب مفاتيح البيئة التجريبية لـ Web Payments.
2. **المفاتيح كـ secrets بإعدادات البيئة (مو بالريبو ولا اللوحة ولا التقارير):**
   | المتغير | القيمة | ملاحظة |
   |---|---|---|
   | `FIB_CLIENT_ID` | من FIB | سري |
   | `FIB_CLIENT_SECRET` | من FIB | سري جداً |
   | `FIB_ENV` | `stage` | نفس الاسم والقيم (`dev`/`stage`/`prod`) المستعملة بدليل الـ SDK الرسمي. بالتجربة يبقى `stage` |
   | `FIB_CALLBACK_URL` | رابط HTTPS عام لـ `/fib/callback` | مو سري، بس يحتاج قرار (النقطة 3) |
   | `FIB_REDIRECT_URI` | اختياري | وين يرجع الزبون بعد الدفع |
3. **رابط callback:** لازم يكون HTTPS ومفتوح من الإنترنت حتى توصله FIB. خيارين يحتاجن قراره:
   - (أ) دومين فرعي تجريبي، مثلاً `sandbox-pay.phi-iraq.org`، على خادم صغير. هذا تغيير إعدادات دومين وخادم، فيحتاج موافقته، ومصطفى يحضّر الاقتراح.
   - (ب) بدون رابط عام: نعتمد الفحص الدوري للحالة فقط، ونأجل اختبار الـ callback. أرخص بس التجربة تبقى ناقصة.
4. **تأكيد:** إن التجربة على الدينار العراقي فقط (التوثيق يكول IQD هي العملة الوحيدة المدعومة)، وبأرقام وهمية.

## 4) المخاطر وحدود التجربة
- **التسجيل غير واضح:** ماكو صفحة تسجيل عامة للبيئة التجريبية، والنموذج يحتاج دخول. ممكن FIB تطلب أوراق شركة حتى للتجربة. هذا غير متوفر لحد ما يرد عليهم المالك.
- **تضارب بالتوثيق:** صفحة الدفع تستعمل `fib.stage.fib.iq`، وصفحة SSO تذكر `fib.sandbox.fib.iq`، والـ SDK عنده `dev`/`stage`/`prod`. لازم نأكد العنوان وية FIB وقت التسجيل.
- **فروقات صغيرة:** صفحة الموقع تحدد الوصف بـ 50 حرف وما تذكر الاسترجاع، ودليل الـ SDK يذكر الاسترجاع وحالات `REFUNDED`. نعتمد الأضيق ونختبر.
- **الـ callback بدون توقيع موثق:** أي أحد يعرف الرابط يكدر يرسل له. الحل: التحقق دائماً من FIB قبل تحديث الفاتورة.
- **التجربة ما تثبت الإنتاج:** البيئة التجريبية ما تتعامل وية الشبكات المصرفية. الرسوم، وسرعة التسوية، وشروط حساب التاجر: غير متوفر. والإنتاج يحتاج موافقة FIB وموافقة جديدة من المالك.
- **بيانات حساسة:** رد الحالة بيه اسم الدافع والـ IBAN. ما ينحفظ إلا بقاعدة التجربة، وما يطلع على اللوحة أو التقارير.
- **الاعتماد على حزمة خارجية:** `@first-iraqi-bank/sdk` تابعة لمنظمة البنك على GitHub. حسب قواعد الشركة، حيدر يقرا الكود قبل التثبيت وننتظر الموافقة. والبديل استدعاء REST مباشرة، وهو بسيط.
- **كود فاي مو بالريبو:** التجربة خدمة منفصلة، والربط الفعلي بوحدة الفواتير يحتاج تقدير ثاني من حيدر.
- **حدود التجربة:** FIB فقط (لا زين كاش ولا Qi)، دينار فقط، فواتير وهمية، بدون إنتاج، وبدون أي زبون حقيقي.
